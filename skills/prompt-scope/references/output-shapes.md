# Output Shapes

完整的渲染样例。用来回答"运行之后屏幕上会出现什么"。需要"优化后的 prompt 长什么样"时，看 `prompt-rewrite` 的 `references/example.md`。

样例经过压缩，真实回答按任务复杂度伸缩，但结构保持一致。

---

## 1. Preflight — 一次完整回答

```text
本次按 Preflight 执行：只读；先给 scope card，再给 findings、覆盖情况与未检查项。

【前提】L1 是 L0 与 L2 之间的索引层，不承载细节
【意图】判断 L1 是否合理、闭环、上下呼应；交付 findings 清单
【场景】Layered docs（主）+ Design review（次）
【基准】职责单一 / 指针双向可达 / 无孤儿重复 / 与源一致 / 容量合规
【必查】1) 上→下指针 2) 下→上可达 3) 同层重复 4) 与源一致
【证据】最小集：root.prizm + 全部 L1 + 被引用的 L2；不读：L2 内部细节
【范围】只评 L1 与 L0/L2 的呼应；不做：改文档、查 git 历史
【未知/假设】假设 L1 = .prizmkit/prizm-docs 的直接子文档
【下一步】只读；停止：4 项必查都有结论或明确受阻

[should-fix][high] core.prizm:12 → 指向的 L2 文件不存在 → 读者无法解析该模块 → 补建 L2 或删除指针 → 链接检查脚本验证
[should-fix][medium] root.prizm 与 core.prizm 重复描述同一模块 → 两层语义漂移 → 职责下沉到 core.prizm → 对比两层文本确认唯一归属
[question][medium] 新增模块 X 没有 L1 条目 → 可能是遗漏，也可能模块未稳定 → 确认模块状态后再决定是否补

覆盖：指针完整性 ✓；孤儿检查 ✓；同层重复 ✓；与源一致（抽样 3 个模块）；容量 ✓；术语（抽样）
未检查：L2 内部正确性；生成物/安装副本；历史漂移。原因是本次契约只覆盖 L1 与 L0/L2 的呼应。
```

这份输出满足了：

- 第一行先回答"我在做什么、会产出什么"，用户不必等结论才知道模式。
- scope card 是可见契约，写在动手之前，不超过 15 行。
- 每条 finding 一行内交代位置、证据、影响、最小修复、验证方式，并带 severity/confidence。
- 覆盖情况区分"已验证 / 抽样 / 未检查"，未检查的给出理由而不是留空。

## 2. 只读确认（Preflight 遇到阻塞时的最短形态）

```text
本次按 Preflight 执行：只读。目前缺一个会改变结论的信息。

"这个设计"指向不明确：是方案能否跑通，还是这个方案是否值得做？
默认按前者检查：目标对齐、失败路径、边界、可验证性。若是后者，会追加替代方案与机会成本。

未检查：其余维度（等确认后再展开）。
```

短回答同样是完整回答：模式、阻塞原因、默认假设、未检查项都在，不因为短就省掉边界。
